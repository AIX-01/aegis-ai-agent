## 2. VLM 파싱 로직 강화 (regex 전환)

LangSmith 확인 결과 vlm_summary 추가 후 파싱 실패율 증가 확인.
파인튜닝 모델이 class1/class2만 출력하도록 align되어 있어 프롬프트 변경 시 출력 포맷 불안정.

### 문제 원인
- 기존 `replace(',', '\n').split('\n')` 방식이 summary 내 쉼표로 인해 class1/class2까지 오파싱
- 모델이 한 줄로 출력 시 `class1=suspicious class2=assault` → class1 값이 `"suspicious class2"`로 오염

### 해결
- `src/clients/vlm_client.py` — 전체 파싱 로직을 regex 기반으로 교체
  - `class1`, `class2`: `re.search(r'class1\s*=\s*(\w+)', ...)` — 단일 단어만 캡처
  - `vlm_summary`: `re.search(r'vlm_summary\s*=\s*(.+?)(?:\n|$)', ...)` — 줄 끝까지 캡처
  - 키워드 폴백 로직 유지 (regex 실패 시)

### 검증 케이스
| 케이스 | 기존 | regex |
|--------|------|-------|
| 정상 줄바꿈 | OK | OK |
| 쉼표 + summary에 쉼표 | summary 잘림 | OK |
| 한 줄 space 구분 | **class1 오염** | OK |
| summary 없음 | OK | OK |
| 자연어 응답 | 폴백 | 폴백 |
| `<>` 감싸기 | OK | 폴백으로 OK |

## 기타 논의 (코드 변경 없음)

### 클립 생성 로직 분석
- `PacketBuffer`가 wall clock 기준 30초 패킷 유지, `mux_packets_to_mp4`로 MP4 생성
- 서버 시작 직후나 Producer 일시 정지 시 30초 미만 클립 생성 가능
- Muxing은 remux 방식(재인코딩 없음)으로 30초 클립 기준 1초 이내 완료

### 윈도우 겹침 원인 분석
- `window_slide=8초`(wall clock 트리거) + `window_size=8`(프레임 개수 선택)의 불일치
- FPS 지터(프레임 도착 간격 불균일) 시 이전 윈도우 프레임 재사용 → 1~2초 오버랩
- 8프레임 × 1FPS = 간격 7개 → 구조적으로 window span은 7초
